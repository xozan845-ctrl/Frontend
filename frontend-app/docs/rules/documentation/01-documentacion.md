# 01 — Documentación como código

| ID     | Regla                                                                                                                                                                                                                                                                                                                                                      |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-DO-1 | **El README describe la realidad**: el `README.md` de la app mantiene al día stack, scripts y estructura. Si un PR cambia la estructura de carpetas o los comandos, actualiza el README en el mismo PR. Prohibido documentar rutas o scripts que ya no existen.                                                                                            |
| R-DO-2 | **ADRs para decisiones**: toda decisión que se aparta de lo obvio o cambia una regla se registra en [`../../decisiones.md`](../../decisiones.md) como `ADR-XX` con fecha, estado, contexto y consecuencias; usa la plantilla [`../../plantilla-adr.md`](../../plantilla-adr.md). Las reglas no se cambian sin un ADR que lo respalde.                      |
| R-DO-3 | **Variables y configuración**: cualquier variable de configuración (`environment`, endpoints, flags) queda documentada junto a su valor por defecto y su efecto. Los secretos **no** se documentan con su valor (`R-SE-2`).                                                                                                                                |
| R-DO-4 | **Comentarios con el porqué, no el qué**: los comentarios explican decisiones no evidentes (por qué se tolera un shape, por qué se difiere un cálculo). Prohibido comentar lo que el código ya dice.                                                                                                                                                       |
| R-DO-5 | **Docs dentro del repo**: la documentación vive en `docs/` o junto al código; prohibido depender de enlaces externos o documentos en `/tmp` que no se versionan.                                                                                                                                                                                           |
| R-DO-6 | **Documentación y reglas viven juntas**: las reglas normativas en `docs/rules/`; los derivados (audit, checklist) en `docs/rules/_meta/`; el guion operativo (`firebase-hosting-setup.md`) fuera de `rules/` pero en `docs/`. Un cambio de regla actualiza el índice del área y el `CHECKLIST` (`R-COV-3`).                                                |
| R-DO-7 | **README por directorio importante**: `docs/`, `scripts/`, `src/app/` y sus capas `core/`, `shared/`, `layout/` y `features/` incluyen un `README.md` no vacío con título que explica su responsabilidad. La lista vive en `REQUIRED_READMES` (`scripts/config/project.mjs`) y se valida con `npm run rules:check`.                                        |
| R-DO-8 | **Docs sincronizadas con el código en PRs**: si un PR cambia lógica/contratos (`src/app/core/**`, capas de `features/` con servicios/estado/repositorios/adapters/models/guards/interceptors/resolvers, `app.config.ts`, `app.routes.ts`, `<feature>.routes.ts` y `environments/**`), el motor exige documentación **del área** (`docs/rules/(architecture | frontend | ui  | security | test)/**`), un ADR (`docs/decisiones.md`) o el README de la capa; los cambios de `scripts/**`exigen`scripts/README.md`o`docs/rules/**`; los de `.github/workflows/**`exigen`docs/rules/ci/**`o`scripts/README.md`. No basta cualquier `.md`de`docs/`. Excepciones justificadas en `DOCS_SYNC_EXEMPTIONS` (`scripts/config/project.mjs`). |

| R-DO-9 | **Cobertura ejecutable honesta**: cada suite declara en `rules` solo las reglas que verifica; las que solo contextualiza van en `cites`. `npm run rules:check` falla si un ID no existe en `docs/rules`, si aparece en `rules` y `cites` a la vez o si la cobertura verificada baja de `COVERAGE_MIN_VERIFIED` (`scripts/config/project.mjs`). |

## Verificación

```bash
git grep -n "src/app/d/" -- README.md docs | grep -v "01-documentacion.md"   # R-DO-1: no debe aparecer
ls docs/rules/_meta                                                          # R-DO-6
ls docs/README.md scripts/README.md src/app/README.md \
   src/app/{core,shared,layout,features}/README.md                           # R-DO-7
npm run rules:check                                                          # R-DO-9: cobertura verificada
```
