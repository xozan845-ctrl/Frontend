# 04 — PR: rama, cuerpo, checks y merge

Cierra el flujo de git: [`01-stage.md`](./01-stage.md) →
[`02-commits.md`](./02-commits.md) → [`03-push.md`](./03-push.md) → **este**.
`main` se alimenta **solo** por merge de PR verificado.

| ID     | Regla                                                                                                                                                                                                                                                                                                                                                            |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-PR-1 | **Rama por trabajo**: prohibido commitear directo a `main`. Cada cambio vive en una rama `tipo/ámbito-descripción` creada desde `main` (`git fetch origin && git pull --rebase origin main && git switch -c <rama>`). Excepción: un incidente se corrige con rama `fix/...` (`R-GB-6`).                                                                          |
| R-PR-2 | **Un PR = una unidad revisable**: un tema, una capa, una decisión (mismo criterio que `R-GC-3` pero a escala de PR). Si el cuerpo dice "y además", el PR se parte; si el segundo depende del primero, se apila (`gh pr create --base <rama-1>`).                                                                                                                 |
| R-PR-3 | **Verificación antes de abrir**: `R-GC-5` en verde para el ámbito tocado. Un PR abierto en rojo solo se admite para pedir opinión, con `[WIP]` en el título, y no se mergea.                                                                                                                                                                                     |
| R-PR-4 | **El cuerpo del PR es la evidencia**: pegar el [`CHECKLIST`](../_meta/CHECKLIST.md) marcado y una tabla de verificaciones **efectivamente ejecutadas** (comando + resultado, no "los tests pasan"). Si una capa de la matriz de [`06-estandares-cobertura.md`](../test/06-estandares-cobertura.md) no aplica, se dice por qué. Un PR sin evidencia no se revisa. |
| R-PR-5 | **Commits trazables**: los commits cumplen `R-GC-1..R-GC-4`; con más de 3 commits, el cuerpo declara en qué commit vive cada parte.                                                                                                                                                                                                                              |
| R-PR-6 | **Checks verdes en la cabeza del PR antes de mergear** (`gh pr checks <n>` sobre el SHA de la cabeza). Run en rojo ⇒ fix-forward con commit nuevo (`R-GP-3`). Cuando exista CI (hoy no hay), ningún merge sin checks en verde.                                                                                                                                   |
| R-PR-7 | **Estrategia de merge: `--rebase`**. El historial de `main` es estrictamente lineal; prohibido `--squash` (destruye la unidad temática y los IDs de regla) y prohibido el merge commit (`R-GB-4`).                                                                                                                                                               |
| R-PR-8 | **Cierre**: tras el merge, rama eliminada (`git push origin --delete <rama>`, local con `git branch -d`) y PR marcado como tal. Prohibido dejar una rama publicada sin PR abierto, o un PR que ya no se mergeará sin `gh pr close` con la razón.                                                                                                                 |

## Verificación

```bash
# main sigue lineal (R-GB-4): debe imprimir 0
git rev-list --merges --count origin/main

# checks verdes en la CABEZA del PR (R-PR-6), no en un run viejo
gh pr checks <n>
gh pr view <n> --json headRefOid,headRefName,mergeable
```
